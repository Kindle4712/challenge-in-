## 挑战二

环境为 Ubuntu 22.04 / WSL 2、RTX 5060 Laptop GPU（8151 MiB）、SGLang 0.5.14、Ray 2.56.0、Qwen/Qwen3-0.6B。

共享与分散前缀组各 32 条请求，最大并发 8，输入 2112 token、输出 16 token。两组均 32/32 成功；共享组缓存命中率 96.97%，实际 Prefill 2048 token；分散组命中率 0%，实际 Prefill 67584 token。报告同时说明公式、延迟变化及 v0.5.14 源码主流程。

## 挑战三

在单机四张 RTX 4090 上启动四个 SGLang 后端，建立一个 Ray head 和四个逻辑 worker，四个 Serve Replica 分别固定访问一个后端。客户端统一经 Ray Serve HTTP Proxy 回放课程固定负载。

正式配置为 A（默认 P2C、并发上限 5）、B10、B20、C（纯前缀亲和）和 D（亲和加当前负载回退）。五个正式配置均完成 64 条预热和 2048 条测量，测量请求全部成功且输出完整。

本次观察中，B20 吞吐最高，B10 尾延迟最低，C 缓存复用最好。D 实际缓解了请求数集中，但增加了重复 Prefill，整体性能没有优于 C/B。报告保留失败轮、参数变化和跨配置比较的限制，没有将负结果写成性能提升。

下载 [正式 ZIP](挑战三/HW3-102503110.zip)，阅读解压根目录的 `README.md`，其中提供安装、集群启动、各配置部署、回放及客户端测试命令。每个正式配置只有一轮成功测量；客户端测试不能替代 GPU 服务端的完整复现。

## 阅读与复现

- 先看各挑战的交付文件，再按对应 README 查找配置和逐请求证据。
- 新实验使用独立结果目录；保留历史失败记录，避免覆盖后失去代码与结果的对应关系。
- 模型权重、Python 环境和缓存不属于交付内容，复现时另行准备。
- 实验日期及补做过程按材料中的实际记录理解；仓库文件更新不等同于课程收集表提交或截止前提交。
